# XLSX, время фото и фоновые задачи

Пользовательские выгрузки создают настоящий Excel XLSX с листами «Сводка» и «Смены». Старые callbacks с `csv` поддерживаются и возвращают XLSX. Числовые даты и время отражают TIMEZONE организации, длительности используют `[h]:mm`. Текстовые значения не превращаются в формулы. Сводка и детали строятся по одному набору строк без прежних пределов выгрузки. Смены относятся к периоду целиком по дате начала.

Время начала и ручного окончания берётся только из исходного Telegram `message.date`. `PendingAction.createdAt` сохраняет этот timestamp; время подтверждения и исполнения worker его не заменяет. Десятиминутное окно начинается при подготовке запроса; сохранение сообщения запроса позволяет восстановить прерванную отправку. Закрывающее действие связано с конкретной сменой. Своевременное фото может исправить автоматическое закрытие по лимиту после задержки обработки, в том числе после открытия следующей смены.

Webhook сохраняет update до обработки; worker использует атомарный claim, порядок по сотруднику, задержку повторных попыток и ограниченную по времени блокировку. У callback нет собственного timestamp нажатия, поэтому для проверки окна используется сохранённое время получения update, а не дата сообщения с кнопкой.

SQL явно квалифицирует схему БД и UTC-параметры. Это исключает зависимость raw SQL от search_path и часового пояса сессии. Типы существующих timestamp и корректные исторические данные не сдвигаются.

Основные расписания заданы в `vercel.json` для каждого deployment Vercel Pro. Требуется CRON_SECRET. GitHub ticks используют матрицу MAIN/COPY/DAILY с отдельными секретами как резерв. Автоматические рассылки выполняются только Vercel, чтобы избежать двойной отправки. Не полагайтесь только на HTTP 200: проверяйте ok/error/skipped, состояние очереди, последний tick_completed и изменения рассчитанных окончаний смен.

Обычные тесты разрешены только на выделенной локальной БД shift_bot_test; очистка полностью квалифицирует таблицы. Тестирование облачного PostgreSQL выполняется на отдельной пустой ветке, с проверкой endpoint, без production и без отправки Telegram-сообщений. Для аудита реальных данных используйте `scripts/auditShiftTimes.ts` (только чтение).

Перед развёртыванием сохраняйте полные pg_dump каждой БД, индивидуальные env и предыдущие deployment IDs в закрытом локальном каталоге. `scripts/reconcileLegacyQueue.ts` применяет проверенный план для конкретного bot ID без повторной отправки исторических сообщений. Миграции добавочные; при откате приложения поля можно оставить. Старые версии не поддерживают GET cron: включите резервные POST ticks. Не восстанавливайте всю БД поверх новых записей без отдельного плана.

Пример на вымышленных данных: `pnpm exec ts-node scripts/generateExample.ts`. Файл в artifacts открывается Excel/LibreOffice. Проверка XLSX охватывает кириллицу, длинный текст, текстовые ID, пустые/открытые смены, 10005 строк и суммы свыше 24 часов.
